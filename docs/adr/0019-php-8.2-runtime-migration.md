# ADR 0019: App runtime and declared PHP floor move from 7.4 to 8.2

## Status

Accepted

## Context

ADR-0011 added dual-version CI coverage (`php:7.4` and `php:8.2`) as deliberate upgrade prep,
explicitly deferring the actual runtime swap: issue #239 called it "a *possible* future upgrade,"
not a committed date, and named "migrate the runtime itself as a separate, later ticket" as the
follow-up this ADR now executes. A prior attempt (#167 / PR #168) tried to raise only the declared
`composer.json` floor to `>=8.3.0` while the runtime stayed on 7.4; the maintainer declined it
specifically for that mismatch — declaring a floor the app hadn't actually reached. Issue #293
reopened the question with both legs already green in CI, and the maintainer confirmed 8.2 (not
8.3) as the target.

## Decision

The runtime and the declared floor move together, to PHP 8.2:

- `run.sh`'s `IMAGE` moves from `php:7.4-apache` to `php:8.2-apache` (container name and help text
  updated to match). The `install` subcommand keeps using `php:8.3-cli` — that choice tracks the
  CI tooling version, not the runtime, and is unaffected by this change.
- `composer.json`'s `require.php` moves from `>=7.4.0` to `>=8.2.0`; `composer.lock` regenerated
  under `php:8.3-cli` to match CI's own dependency resolution.
- The `phpunit` and `e2e` CI jobs drop the `["7.4", "8.2"]` matrix and the 7.4-specific branching
  (`platform.php` pin, PHPUnit `^9` downgrade, psalm removal, `phpunit-9.xml.dist`) — there is no
  7.4 leg left to cover. Each collapses back to a single job on `php:8.2-cli` against the ordinary
  lockfile, the shape they had before ADR-0011 introduced the matrix. Static analysis jobs
  (PHPStan, Rector, Psalm taint, PHPMD, Composer audit, coverage floor) stay on `php:8.3-cli`,
  unchanged — consolidating those was explicitly out of scope per #167's own MR-scope note.
- `phpunit-9.xml.dist` is deleted: it was only ever used by the now-removed 7.4 leg.

## Consequences

- ADR-0011's dual-version matrix has served its purpose (verifying the 8.2 upgrade target ahead of
  the swap) and is retired now that there's one runtime version again; ADR-0011 is marked
  Superseded by this ADR.
- The `docs/refactoring/out-of-scope/php-minimal-version.md` reversal marker (`Blocked by:
  PHP >= 8.3.0`) is unaffected by this change: 8.2 does not satisfy its 8.3 trigger, exactly as
  ADR-0011 and issue #239 flagged. A future scan raising the declared floor to 8.3 is a distinct,
  later decision, not a continuation of this one.
- The app's own README security warning (known unpatched vulnerabilities, local-only) is unchanged
  by a runtime-version move — the PHP version was never the source of those findings.
